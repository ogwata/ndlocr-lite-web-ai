このリポジトリの開発ルール:

1. **プッシュは絶対にユーザーが指示するまでしない（最重要ルール）**
   - プッシュすると再デプロイが走り、ユーザーに迷惑がかかる
   - 「プッシュして」等の明確な指示があるまで絶対に `git push` を実行しない
   - 2026-03-26に無許可プッシュで厳重注意を受けた。二度と繰り返さないこと
2. **コミットは機能ごとにまとめるなど、Claudeの判断でしてよい**
3. **変更したら、ユーザーの指示を待たず、変更内容をドキュメントに記録する**
   - README.md（特徴、技術スタック、変更履歴）
   - CLAUDE.md（技術仕様、ディレクトリ構成、UI設計仕様）
   - docs/NDLOCR-Lite-Web-AI-開発計画書.md（技術スタック、UI設計）
   - 各ドキュメントの目的に沿った形で記録する

**Why:** プッシュ＝本番デプロイのトリガーであり、ユーザーがタイミングを完全に制御する必要がある。ドキュメント更新は都度やらないと漏れる。

**How to apply:**
- コード変更後、同じコミットまたは直後のコミットでドキュメントも更新する
- `git push`は絶対にユーザーの「プッシュして」等の明確な指示があるまで実行しない
- コミットは機能単位で適切にまとめる（バグ修正、機能追加、ドキュメント更新等）
