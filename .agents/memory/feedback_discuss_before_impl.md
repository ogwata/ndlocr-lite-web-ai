---
name: 実装前に必ずユーザーの許可を得る
description: 設計方針の説明後、ユーザーの明確な許可があるまで絶対にコードを書き始めない。方針説明と同時に実装を始めるのも禁止。
type: feedback
---

実装を始める前にユーザーと議論し、明確な許可を得ること。

**Why:** ユーザーから複数回指摘。方針説明と同時にコードを書き始める行為も禁止された（2026-03-26）。許可なく実装するとテスト負担が増え、手戻りも発生する。

**How to apply:**
- 設計案を提示 → ユーザーの「はい」「お願いします」等の明確な承認を待つ → 実装開始
- 方針を説明するメッセージの中でツールコールを含めない（説明と実装を同時にやらない）
- 承認前にコードを1行も書かない
- 大きな変更は特に慎重に。UI変更や動作フロー変更は必ず事前確認
